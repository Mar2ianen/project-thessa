# Аудит оптимизаций: 12 сентября 2026

Проверенная база: `45e0b79` (включая новые SIMD kernels, табличный Verlet,
head/extend/trim кеш и пакетный coast). Изменения этого прохода локальные.

## Исправления

- `run_table_loop`: после полного принятого шага `end_snap` меняется местами
  со `start_snap`, `acceleration_1` становится начальным ускорением следующего
  шага. Для N полных шагов теперь N+1 снимков и расчётов ускорения вместо 2N.
  При частичном impact переиспользования нет; новый вызов extension заново
  семплирует начальную точку своей таблицы.
- `propagate_sampled_extend`: проверяются согласованность массивов, конечность
  состояния/времени и шаг. Ошибка после частичного дополнения откатывает длины
  массивов, сохраняя согласованность с исходными metadata.
- SIMD wrappers 4/8: `base.checked_add(width)` закрывает переполнение индекса
  перед unsafe pointer arithmetic. Ранее в release переполнение могло пропустить
  неверный индекс через проверку длины.
- Scalar gravity fallback пропускает негравитирующие тела до проверки расстояния;
  нулевая дистанция до тела без гравитации не является сингулярностью поля.
- `trim_before`: интервал применяется к накопленному удаляемому блоку. Раньше
  он лишь откладывал первую очистку, после чего происходил memmove каждого
  следующего устаревшего отсчёта.
- Head bake уважает нулевой бюджет; scaled display paths не запрашивают
  неподдерживаемое uniform extension.
- Пакетный coast не вызывает allocator спекулятивно перед возможным fallback:
  это могло дважды продвинуть actuator slew в одном тике. Вращение с активным
  assisted RCS/SAS оставлено пошаговому управлению, поскольку нулевой момент
  в начале интервала не гарантирует нулевой момент позже.
- `rails_time_advanced_s` включено в actual advancement/effective warp, overlay
  и CSV (`rails_advanced_s`). Старые JSON captures читаются с нулевым значением.

## Измерение

Команда: `cargo bench -p thessa-sim-core --bench onrails`, portable release,
runtime SIMD dispatch. Система из 22 источников, 40 000 шагов / 40 001 точка.

- До изменений: 24.011 мс (один базовый прогон).
- После: медиана 18.870 мс, диапазон 18.609–20.465 мс в семи повторениях.
- 256 тёплых выборок: p50 4.7–5.2 мкс.

Это измерение CPU-запекания, а не FPS игры; относительный выигрыш ориентировочный,
поскольку базовая версия измерена одним прогоном. Логи находятся в `work/`:
`sep12-user-blaze-baseline.log`, `sep12-blaze-bench-repeats.log`,
`sep12-blaze-workspace-tests.log`, `sep12-blaze-clippy.log`,
`sep12-simd-release-tests.log`.

## Границы результата

Пакетный shortcut требует нулевой аэродинамической нагрузки и доказанного
отсутствия контакта на интервале. Название режима Coast само по себе не означает
вакуум: экспоненциальная атмосфера может возвращать ненулевую плотность высоко
над поверхностью. Произвольное асимметричное вращение не заменено постоянной
угловой скоростью.

Trim освобождает прошлые точки, но не сбрасывает лимит accepted_steps: по
исчерпании общего горизонта всё ещё нужен новый bake. Этот аудит не доказывает
бесконечное продление одной траектории. Новые renderer/terrain изменения в этом
проходе прошли workspace проверки; отдельного визуального/FPS прогона не было.
