# 124 — Ground scan normals in the existing material pages

Status: the missing scan-normal input is implemented and verified. This closes
one concrete cause of poor close-ground shading; transient/coarse residency,
submillimetre geometry, moving-camera acceptance and reference parity remain open.

## Cause and retained change

The three existing CC0 floor scans supplied colour, roughness and displacement,
but their OpenGL normal maps were not imported. The old optical normal plane
was derived only from the filtered displacement plus procedural grain. The
normal maps contain substantial additional slope detail. Increasing framebuffer
resolution or tessellating the same filtered height cannot restore that input.

The companion `*.normal.bin.gz` files preserve RGB8 OpenGL normal data at the
existing 1024/512/1024 source resolutions. The importer verifies pinned source
hashes; its 512-square reduction averages slopes before normalizing. Original
colour/roughness/height files remain unchanged. Exact source/processing identities
are in the adjacent `*.normal.provenance.json` files and CC0 license notices.

`ground_detail::normal` converts source normals into physical chart gradients.
Image-row V is opposite OpenGL normal Y. Each mip removes the gradient of the
same filtered displacement at the same footprint; the normal is therefore a
**residual**, rather than a second copy of the source height slope. A periodic
swatch's mean tilt is removed. One folded moss-source texel has nonpositive Z;
it uses the source height slope before detrending, since a height graph cannot
represent an overhang. There is no division by a negative/zero Z or final
radiance clamp.

The colour and normal planes share the existing stochastic phase, quarter-turns,
blend weights, triplanar projections and physical source widths. Gradients use
the inverse UV rotation, are projected into body space, then enter the existing
metric-correct face-chart solve. Moss residual amplitude matches the existing
half-amplitude moss height contribution. Ground/snow/cover weights retain their
existing ownership. This is an optical normal representation, not additional
collision geometry or a calibrated change to the planet's physical height.

## Controls and cost

The existing shared `[renderer] terrain_ground_detail` and `terrain_normal_maps`
controls gate this source. Low/Medium/High retain the existing source ceiling,
normal-mip filtering and material-page budgets. No additional production toggle,
GPU texture, binding, render pass, triangle or temporal history is introduced.
Normals Off returns before sampling or lazily decoding the new sources.
Coarse footprints above the swatch scale return zero residual without decoding.

All three residual pyramids together contain 25,165,816 bytes of CPU f32 data,
lazily retained with the existing source owner. Packed companions add about
6.69 MB to assets. The existing release 32-paired-page workload ran on both
versions: ground-detail-On median approximately 153.7 → 158.9 ms/page;
ground-detail-Off control 122.8 → 125.4 ms/page. These one-pass CPU timings
include normal material generation, not frame time, and do not establish a
speedup or a universal startup bound. Source decoding is included in the first
applicable page; GPU storage/sample counts remain unchanged.

## Executed controls

- 292 worldgen tests passed after the source implementation. The subsequent
  adjacent-page/disabled-normal test also passed: normal and base-normal aprons
  agree, and disabling normals preserves colour and liquid coverage.
- A periodic synthetic surface checks source-height subtraction at every mip;
  an independent numerical plane checks all inverse UV quarter-turns. Actual
  assets have finite residuals, zero unresolved mean and continuous stochastic
  phase. This is a scoped filtering/transform oracle, not a universal angular
  error bound for RG8_SNORM or arbitrary displacement.
- Four canonical frozen-erosion pages at L20–L23 were generated by the old and
  new implementations. Albedo/roughness, base normals and liquid coverage are
  byte-identical; only the optical normal plane changes.
- Actual B03 ran at 1920×1080, 4× MSAA, full High plant demand, EV11/12° sun,
  20-second readiness and the retained bounded 1024²/100 m shadow setup. All 20
  diagnostic views complete, with exact within-run depth, receiver and beauty
  round trips. HDR has no negative/nonfinite channel.
- Across the old/new readiness controls, depth, topology, visible geometry-kind,
  height-page-level, albedo, roughness, water and desired-LOD images are all
  byte-identical. Vertex position, geometric normal and chart coordinates are
  also identical. The raw vertex buffer differs only in physical height-slot
  indices; publication generations/epochs differ across processes. No general
  independent-process replay claim is made.
- On 287,609 selected near-ground quads, a normal mixed-difference RMS changes
  0.04168 → 0.11391. This measures restored detail, not subjective realism.
  A matched unlabeled FHD pair is prepared; no blind vote/acceptance is invented.
- Shared stream tests (33), client compilation and strict worldgen/native/stream
  Clippy pass. Commands, binaries, source patches, exact controls and limits are
  in [the artifact](artifacts/ground-scan-normals-2026-11-03.json).
