# Flight/HUD diagnosis — 2026-09-09

Evidence: preserved `pilot-flight-2026-09-09.csv` (0–37.436 s), local
`target/flight-traces/pilot-flight.csv` (first inspected 0–256.532 s), and
user screenshots at 176 s and 619 s. The local capture can continue growing;
statistics below refer to the inspected segment.

## Independent faults

1. **Aerodynamic/control signs.** With +X forward and +Z up, physical right is
   -Y. The aft horizontal tail had `lift_coefficient_sign=-1`, so positive
   alpha produced nose-up torque instead of nose-down recovery. The old unit
   test incorrectly named that negative-Y torque "restoring". Elevator,
   rudder and aileron mapping now agrees with the actual GLB nose movement.
   W/S is down/up, A/D left/right. The generic signed-lift API is retained, but
   its misleading documentation and its use in the starter tail are corrected.
2. **Competing synthetic assists.** The old SAS, horizon correction, alpha trim,
   direct command torque and aerodynamic surfaces could fight each other.
   The trim term was not conditioned on atmospheric density, and its forward
   speed denominator was clipped. This also opposed large orbital attitude
   changes. These synthetic moment paths are removed. The allocator now drives
   actual surfaces and bounded opposed RCS force pairs. Manual SAS input requests
   a rate and captures the achieved attitude; no accumulated target can wind
   past the shortest-path boundary. RCS-limited braking prevents overshoot.
3. **Rendering precision, distinct from rigid-body oscillation.** Craft and
   camera accumulated launch-relative f32 translations. A long flight reduces
   vertex precision and can make small mesh features jitter or appear separated.
   The craft is now the render origin, all its meshes remain near zero, and the
   planet translation is subtracted in f64 before conversion. Pilot clip planes
   no longer inherit the map's compressed-coordinate settings.
4. **Camera clamps.** Pitch was clamped in both input and render stages, and
   look-at always used world-up. Quaternion orbit removes the limits and keeps
   a continuous camera-up vector while crossing the poles.
5. **Misleading instruments.** The old UI overlaid fixed-position cards, showed
   an invented FPV/target cue, clamped negative periapsis to zero and reused datum
   as AGL without terrain. The new default is compact; extra data is opt-in.
   Sphere/cue horizontal axes now agree with the physical right direction.

The fresh segment reached AoA 60+ degrees with zero axis input around 30–50 s,
then the spherical surface boundary around 55 s. The archived capture contains
an additional numerical excursion: Mach 23.09 and q 30.84 MPa around 27.8 s;
these old values should not be treated as credible flight performance.

## Regression coverage

Production-path tests cover fifteen minutes with equal elapsed time split into
20 ms and 7+13 ms render frames, actual mesh-nose response to W/S/A/D, control
mode changes, and orbital pitch/yaw turns beyond 360 degrees at 300 km altitude.
The orbital case disables the engine and uses the actual atmosphere/gravity;
SAS holds after release rather than snapping back at 90/180 degrees.

Captured diagnostics now have unique timestamp/PID filenames and add mode,
actual normalized surface commands, saturation and target quaternion. State and
forces in each CSV row come from the same fixed physics step. F1 lists the
current layout; unimplemented KSP actions are not advertised as working.

## Captured high-rate stop and numerical fix

`2026-09-09-high-rate-stop.csv` preserves 7989 complete rows,
514.808333--581.375000 s, from flight PID 503852. Direct-mode commands led to
large body rates; the explicit-Euler gyroscopic update then increased energy
without external work. The terminal rate norm approached the 25 rad/s guard.
This was a flight-solver stop, not an application-process crash.

A zero-torque test using the capture's spin scale fails on the old integrator
with relative energy gain 0.000625833 in its first step. Implicit midpoint plus
a paired Cayley quaternion update retains physical gyroscopic motion without
adding damping or changing inertia. Over 60 s, maximum relative energy error
is 5.30e-13 and inertial angular momentum error is 6.51e-13.

The production regression restores the first recorded state and replays only
the pilot commands, recomputing forces through the actual world/aero pipeline.
It reaches 641.375 s, including 60 s beyond the recorded stop; peak rate is
10.795882 rad/s, final rate 5.169897 rad/s.

The live visual check showed coincident mesh origins and scale/orthogonality
errors below 1e-6 through the user's ~9.7 minute flight. No renewed visual
separation was reported before the solver stop; this is separate from the
stronger, automated numerical-rotation regression above.
